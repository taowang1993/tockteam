## Confirmed Findings — 3 Total

1. **[P2] A failed or wrong-generation tree refresh left stale Base rows available.** Impact: after a vault change, a failed inventory request could leave old filters, results, and exports visible as if current; a wrong-generation response also silently returned without invalidation. Affected: `plugins/tocktutor/packages/tockteam-tocktutor-workbench/src/route.tsx` (`refreshTree`, `hydrateBaseRows`). **Fixed/verified:** mark the inventory untrusted, abort prior hydration, clear loaded rows, show unavailable, and refresh the tree before Retry. The two route regressions each failed on the old `ready` state and now pass, including recovery after a fresh inventory. An aborted or superseded request still leaves the newer request in charge.
2. **[P2] Reopening the same Base path in another vault retained the old vault's view and search.** Impact: a filter query and view choice from one vault could make the next vault's valid rows appear missing. Affected: `plugins/tocktutor/packages/tockteam-tocktutor-workbench/src/route.tsx` (`TockTutorRouteView` state reset). **Fixed/verified:** reset pane-local Base controls on vault identity/generation as well as path change. The mounted component regression failed before the change and now selects the new vault's first view with its full result set.
3. **[P2] A Base with an inline comment on `views:` could be read but not configured.** Impact: the valid Base table rendered, yet Rename View and Add View returned no source update. Affected: `plugins/tocktutor/packages/tockteam-tocktutor-workbench/src/base-authoring.ts`. **Fixed/verified:** both authoring entry points recognize the same commented section header as the parser and preserve its bytes. The source-authoring regression failed on `null` before the fix, then passed. The guarded Desktop flow renamed a view and added another while retaining `views: # Keep collection comment` and the unrelated view.
