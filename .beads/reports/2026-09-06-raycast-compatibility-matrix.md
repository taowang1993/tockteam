## Executive recommendation

The user goal is to run existing Raycast extensions, ideally unchanged. Static evidence supports researching a **trusted Cordis-owned compatibility host** that reimplements public Raycast APIs and Node semantics without copying private Raycast RPC. That is distinct from loading each arbitrary extension as a trusted Cordis plugin; the latter would enlarge the trusted composition and supply-chain surface. Neither trust posture is approved by this report.

Missing Raycast wire protocol is not inherently a source-compatibility blocker: a host can provide equivalent public API behavior. It does prevent claiming binary/runtime protocol compatibility. Exact unchanged execution still depends on package/runtime, native-module, service, and API edge behavior not established here.

Proposed first command targets (recommendations only):

1. **Google Translate — `translate` view command**: exercises List/actions, preferences, clipboard, and HTTP translation. `simple-translate.ts` is a helper, not the command name. The separate `translate-form` command expands coverage to Form. Audio (`afplay`, temp file) is a native/action edge that must be implemented or explicitly reported unsupported, not silently ignored.
2. **VS Code Recent Projects — `index` plus open flow**: exercises List, filesystem/state reads, and CLI `execFile`; installed VS Code, platform paths, and open action remain explicit dependencies.
3. **One search command from Linear or Notion**: exercises OAuth/token compatibility and remote search. Provider app registration, redirect, account, scopes, and network remain separate dependencies. A read-only UI flow does not imply read-only authority: Linear requests `read write` in `src/api/linearClient.ts:40-41`. Notion explicitly depends on `https://notion.oauth.raycast.com/authorize` and `/token`, with a personal-token alternative (`src/utils/notion/oauth.ts:17-24`). Neither hosted OAuth service reuse nor reduced scopes has been verified. Exact command selection is intentionally open.

Kill Process is a later capability stress case, not automatically safe merely because its dependency set is small.

## Open trust/compatibility decision and gaps

Decision in plain language: **Will TockTeam run a compatibility host as trusted local code, or require capability mediation—and, separately, may arbitrary extensions enter that host?** A trusted Cordis-owned host is not the same as treating every extension as a trusted Cordis plugin. The owner must decide before implementation. The docs do not define complete RPC wire format, cancellation, isolate termination, limits, manifest negotiation, or unchanged package/runtime behavior. No Raycast oracle, trace, runtime test, dependency safety/license resolution, native asset execution, OAuth redirect, SDK terms, or service terms was checked. These remain unresolved; static findings are not working compatibility.

No runtime tests were appropriate for this research-only report. Planning remains gated on the owner's trust/compatibility decision.
