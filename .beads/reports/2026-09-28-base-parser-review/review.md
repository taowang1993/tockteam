# TockTutor Base View Parser Follow-Up

Snapshot review of the current Base feature after the earlier 13- and 8-finding reviews (both already remediated). Read `.agents/references/tocktutor.md` first. Applied the review skill's simplification, security/hardening, and performance references, then re-reviewed the changed parser and tests through all three lenses. Vault-authored `.base` source crosses into a browser-side query and projection; a misleading filter can expose notes a user expected to hide in that view. Parsing remains bounded, source-preserving, and dependency-free.

**Total confirmed findings: 2. Both fixed and verified.** Paths below are relative to `plugins/tocktutor/packages/tockteam-tocktutor-workbench/`.

1. **[P2] Duplicate formula definitions widened Base filters.** Impact: `visible: note.active == true` followed by `visible: true` displayed a note whose `active` property was false, despite a `filters: formula.visible` restriction. Empty/undeclared first definitions could also be silently ignored. **Affected:** `src/base-parser.ts:178–187`. **Fix/verification:** duplicate, empty, and unsupported formula declarations now fail closed; a red-then-green `tests/base-executable-port.test.ts` regression and the isolated Desktop `/tocktutor/Ambiguous.base` alert prove no grid is shown.
2. **[P2] Empty inline list items silently disappeared.** Impact: `order: [file.name,, note.active]` displayed a seemingly valid view with a silently altered column list; `[ , ]` could be mistaken for an empty configuration. **Affected:** `src/base-parser.ts:64–96`. **Fix/verification:** reject empty list entries for `order`, `sort`, and `summaries`; retain valid empty `[]` and a trailing comma. A red-then-green parser regression and the isolated Desktop `/tocktutor/Malformed.base` alert prove no partial grid is shown.
