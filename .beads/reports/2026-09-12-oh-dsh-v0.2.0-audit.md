# Oh-DSH v0.2.0 Selective Port Audit

## Result

Oh-DSH `v0.2.0` contains three groups worth considering for TockTeam:

1. **Adapt now:** browser-local assistant-response PNG export.
2. **Adapt now:** focused pinned-summary usability and accessibility improvements.
3. **Port only missing regression coverage:** Marketplace protection/filtering, macOS installer retry/idempotency, version fallbacks, and selected updater failure/redaction scenarios.

Do not wholesale port the standalone updater button, Codecov setup, expired DeepSeek V4.1 Flash catalog entry, Oh-DSH branding, release metadata, shell-installer infrastructure, or alpha-era DSH dependencies.

This initial audit approved no implementation by itself; its disposition ledger records the decisions at audit time. The later approved implementations, resolved update-indicator/coverage decisions, final hosted gates, and explicit RC.1 projection follow-up are recorded in [Final Verification](oh-dsh-v0.2.0-final-verification.md).

## Recommendations

### Adapt: Browser-Local Assistant PNG Export

The behavior fits Desktop and Web because it is entirely browser-local. It must not add Host IPC, filesystem authority, an HTTP endpoint, or TUI behavior.

Use the current RC.1 seam rather than copying the alpha-era package:

- `dsh-client-ui-chat` declares `conversation.chat.assistant-actions` for finalized assistant messages.
- The compiled RC.1 chat renderer still emits `data-chat-flow-kind` and `data-turn-tail` markers.
- Oh-DSH's direct `@deepseek-ai/dsh-client-ui-primitives@0.1.2-alpha.3` dependency is incompatible with TockTeam's RC.1 cohort and is not exposed by an RC.1 renderer alias.
- Use TockTeam controls, Lucide, Tailwind, locale lifecycle, package identity, and existing build/staging machinery.
- Treat Oh-DSH's bounded sibling lookup, pixel scan, headroom, crop, and frame logic as a candidate algorithm until verified against the real RC.1 DOM and canvas behavior.

Likely seams:

- new TockTeam-owned browser plugin package;
- `cordis.patch.yml` and `web/cordis.patch.yml`;
- `src/profile.ts`;
- `scripts/build.mjs` and `scripts/stage-dsh.mjs`;
- `web/package.json` and focused composition tests.

Required checks:

- focused contract and package/staging tests;
- bounded Playwright verification of finalized action placement and downloaded PNG;
- Markdown, code, tables, inline images, fonts, dark/light/skin backgrounds, long output, horizontal overflow, CORS/font failures, canvas limits, and download failure;
- unload/session-switch behavior during capture and React singleton verification.

### Adapt: Pinned-Summary Usability and Accessibility

Keep TockTeam's current derivation, compatibility storage key, binding reconciliation, `mountChromeSurface`, right-panel reservation, and layout ownership.

Worth adding:

- bounded preview with expansion and full-text copy;
- explicit loading, error, blank, and empty states using fields verified in RC.1 fixtures;
- stable panel identity and trigger `aria-expanded`, `aria-controls`, and `aria-haspopup` relationships;
- closed-state `inert`, Escape behavior, appropriate initial focus, and focus restoration;
- restricted safe Markdown rendering without a new Markdown dependency.

Do not automatically copy:

- guessed artwork projection schemas;
- Git/PR dashboard sections;
- floating-menu dismissal assumptions that conflict with TockTeam's persistent layout-reserving pane;
- a new styling owner or untrusted `innerHTML` renderer.

If Git metadata is later desired, reuse the existing authorized session-and-cwd request path. Renaming Oh-DSH's URL is not sufficient.

### Adapt: Missing Regression Coverage

Selectively transfer tests, not upstream APIs or architecture:

- Marketplace protected uninstall/enable/disable, manifest-name protection, empty filtering, and recovery after rejection.
- macOS staged-validation failure followed by retry, plus repeated replacement preserving distinct backups.
- version normalization, manifest/layout fallback, and no-version fallback while preserving TockTeam's manifest-before-tag precedence.
- updater failure and credential-redaction scenarios applicable to `tests/app-update.test.ts`.

Do not add cancellation, scheduled-install, command-dispatch, or updater-window APIs merely because Oh-DSH tests them. Avoid its timing-dependent backup-exhaustion test.

### Defer — Decision Required

- **Update indicator:** useful status policy, but TockTeam has no approved click destination. If approved, integrate a small component into the existing Desktop React shell, subscribe to `appUpdate`, and avoid the standalone package, DOM observers, custom tooltip, and invented updater-window IPC.
- **Coverage/Codecov:** optional developer infrastructure. Adopt only through a separate CI decision, with report-only coverage, bounded execution, pinned actions, and explicit suite scope.

### Reject or Skip

- The DeepSeek V4.1 Flash entry explicitly expired after 2026-09-10. Do not ship it or shadow runtime/user catalog ownership.
- Do not copy Oh-DSH's standalone updater package or second staging abstraction.
- Do not add the updater to Web or TUI.
- Do not copy Oh-DSH branding, README hero, translation-pair records, implementation notes, release version, shell installer suite, or release process.

## Security, Migration, Packaging, and Release Impact

- **Security:** no approved candidate needs a new trust boundary. PNG export remains browser-local. Existing Marketplace, workspace authorization, Electron isolation, updater IPC parsing, and Web loopback rules remain unchanged.
- **Migration:** none. No data roots, sessions, profiles, credentials, or user-owned bundle files change in this audit.
- **Packaging:** an approved PNG port would require one new browser package and a frozen dependency closure across Desktop and Web, with no TUI enrollment and no alpha/RC cross-cohort package.
- **Release:** do not adopt Oh-DSH's product version, updater ownership, release assets, or Codecov credentials. The stable baseline in `.agents/skills/oh-dsh/SKILL.md` remains `v0.1.12` until selected ports are implemented, verified, committed, and the skill is validated.
