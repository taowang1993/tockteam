## Pinned Commands and Provider Rules

1. **Notion `search-page` — existing Raycast login is not portable.** Its `src/utils/notion/oauth.ts` uses Raycast's `notion.oauth.raycast.com` authorization/token gateway and a Raycast client ID. Notion's public-connection documentation requires a separately registered connection, allowed redirect and protected client secret. The extension also offers a user-provided token preference, but that is not a PKCE test. Do not reuse Raycast's registration or hijack its callbacks.
2. **Spotify `nowPlayingMenuBar` — feasible *with a new registered client ID*, not with the pinned one as-is.** Its `src/api/oauth.ts` hardcodes a Spotify client ID and uses `OAuth.RedirectMethod.Web` through `@raycast/utils`. Spotify documents public-client PKCE and explicitly permits a registered `http://127.0.0.1` loopback redirect with a dynamically chosen port; `localhost` is not allowed. The user or TockTeam would need to register its own app and consent to its requested permissions. The pinned menu asks for playlist, library, follow and playback modification scopes; it is not a least-privilege first read-only test.
3. **Linear `search-issues` — best read-only candidate *if a separate application can be registered*.** Its `src/api/linearClient.ts` calls the Raycast-specific `OAuthService.linear` helper with only scope and an authorization callback. The pinned `@raycast/utils@2.2.6` implementation defaults to `linear.oauth.raycast.com` for authorization, token exchange and refresh, plus Raycast's client ID; it *can* accept overrides, but this pinned extension supplies none. A separately reviewed, locally adjusted candidate would therefore be needed; the unchanged command cannot be advertised as TockTeam login. Linear documents a separate OAuth app with registered redirect, PKCE `S256`, `read` scope, client-ID-only refresh for PKCE and token revocation. Its docs show a loopback callback example; registration still has to accept the chosen exact callback. The selected adapter would need an explicitly reviewed candidate change to supply TockTeam-owned endpoint/client values (or an equally transparent first-party override), keep tokens out of renderer projections, and prove callback cancellation/revocation before a real account test. An app registration requires an authorized Linear workspace owner; none was available or used in this review.
4. **Slack `search` — not a better PKCE pilot.** Its `OAuthService.slack` requests a broad collection of read and write scopes and optionally accepts a user-provided access token. That token path is not a PKCE proof, and the Raycast-specific helper is not portable without separate registration.

The pinned utils behavior was inspected as inert package bytes from the exact lockfile version (`@raycast/utils@2.2.6`); `npm pack --ignore-scripts` did not execute it.
