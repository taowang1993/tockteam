# Can I Use Preferences and Theme Proof

## Verified Integration

Unconfigured Can I Use sessions now show a first-party, finite preferences form **without spawning or importing upstream code**. Main stages and checks the pinned candidate/data, then offers an explicit, editable exact-target list from the reviewed snapshot. This does not enable the `defaults` token or dynamic Browserslist queries. Path/environment controls are not exposed; project configuration stays unavailable.

Only current owner/session/generation/revision-bound form handles may update the four supported fields or submit. Main validates and detaches all six preferences before calling the persistence adapter. Invalid targets remain editable and never save or start source. Replayed in-flight submissions fail; closing during persistence cannot reopen the command. A successful save starts a new source session/generation. An authenticated Preferences action first retires the old source before opening the form.

Text drafts reach main on input, before keyboard Continue, without the legacy 128-character truncation. Can I Use permits bounded 4096-character field messages; the exact-query validator independently enforces its 4096-byte limit. The form uses the existing finite renderer and native controls.

Actual theme changes send a current main-owned theme handle, immediately disable the old UI interaction state, and restart the source with fresh identities while preserving the root search. An unchanged theme does nothing. **A theme change returns an open detail to its prior root search**, rather than restoring the detail. Browser filtering inside details remains intentionally unavailable; all 14 support rows can be scrolled.
