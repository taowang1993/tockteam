# Plan: DSH 0.1.2-rc.1 Ecosystem Migration

## Problem

TockTeam is pinned to DSH `0.1.1-rc.2`, Better Sidebar `0.15.2`, and dsh-TUI `0.9.2`. The current ecosystem misses newer runtime contracts and upstream security fixes for workspace confinement, terminal escape handling, extension trust, and local data permissions. Oh-DSH migrated to `0.1.2-alpha.3`, but those pins are already superseded and its assembly cannot be copied into TockTeam safely.

## Solution

Migrate TockTeam as one staged compatibility cohort to DSH `0.1.2-rc.1`, Better Sidebar `0.18.0`, and dsh-TUI `0.10.0-beta.5`. Preserve TockTeam-owned launchers, profiles, data roots, updater authority, settings restrictions, Marketplace transitions, terminal park/close semantics, and browser/Desktop trust boundaries. Adapt the composer and shared floating chrome only where the new runtime requires it, and port the Marketplace race regression.

## Implementation Decisions

- `dsh-source.json` remains the canonical runtime source and retains both tarball SHA-512 and generated pnpm-lock integrity.
- Runtime staging remains self-contained. Update `scripts/stage-dsh.mjs`, the exact runtime lock, Windows hoisted layout handling, and Nix assembly together.
- DSH Profile + Loader remains the only composition mechanism. No second agent loop, plugin loader, or direct upstream source patch is introduced.
- Treat store, strict slots, settings, launch-token authentication, composer input shape, Sidebar, and TUI compatibility as one migration contract.
- Better Sidebar stays a submodule release with a guarded downstream adapter. Preserve TockTeam's removed `open.external` authority and terminal `park` versus `close` protocol.
- dsh-TUI stays a pinned renderer. Preserve TockTeam's profile, storage roots, identity, and refusal to self-update through `/update`.
- Keep compatibility styling in `plugins/skins/src/client/tailwind.css`; do not add a stylesheet or embed CSS.
- Runtime-generated capability endpoints and authentication material stay Host-owned and must not be exposed as browser configuration.

## Testing Decisions

- RED seams: source/runtime integrity tests, settings-boundary tests, profile composition tests, Sidebar workspace escape tests, TUI adapter tests, composer input tests, chrome selector tests, and the Marketplace async regression.
- GREEN checks: focused `node --test` invocations after each vertical slice.
- Cohort checks: root and TockTutor tests/typechecks, build, staged runtime smoke, Web smoke, Desktop Playwright flows, interactive TUI probe, and Docker Nix x64/arm64 builds.
- Security checks must prove workspace symlink confinement, authenticated runtime access, settings allowlisting, OSC sanitization presence, and pinned-renderer update ownership.

## Out of Scope

- Copying Oh-DSH's obsolete `0.1.2-alpha.3` lock or package names.
- Adding Oh-DSH's local shell installer.
- Adding an unsandboxed Marketplace build/preview fallback.
- Replacing TockTeam's package/app updater or data roots.
- Editing upstream submodule source for downstream-only behavior.

## Risks

- DSH 0.1.2 changes several service and client contracts together; partial upgrades can load but fail at runtime.
- Submodule releases may contain unrelated behavior. Downstream adapters must remain guarded and fail closed.
- Launch-token authentication can make smoke checks appear healthy while individual HTTP or WebSocket paths remain unauthenticated.
- TUI security tests are source-tree checks; TockTeam must also prove the staged artifact contains the reviewed code.
- Nix and Windows pnpm hoisting differ, so both assembly layouts need explicit checks.
