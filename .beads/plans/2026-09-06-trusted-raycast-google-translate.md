## Process ownership and Cordis seam (proposed, source-backed)

Electron **main** owns `BrowserWindow` creation (`createLauncherWindow`), launcher session/security, catalog/search, `LauncherActionStore`, invocation effects, ranking (`src/main.ts`), and guarded channels registered by `registerLauncherIpcHandlers`/`registerLauncherOwnedIpcHandlers`. The existing launcher preload is only `contextBridge` plus `createLauncherPreloadBridge`; `LauncherSearchResponse` and invocation currently cannot represent views. DSH **Host** is the separate DSH runtime/plugin process loaded through the `@tockteam/desktop` export (`src/plugin.ts:64-153`) and `cordis.patch.yml` insertion; its Cordis `Context` does not cross into Electron main or the renderer.

Proposed single capability package: `@tockteam/trusted-raycast`, exposed using the repository's bundled-package convention, with `/host` (Cordis activation), `/contract` (pure validators), `/runtime` (trusted child), and `/renderer` (first-party view adapter) exports. Add its Host identifier to Desktop-only profile/patch/build/package admissions; do not inject extension React into the Web client. The Host `apply(ctx)` activates this one capability through `ctx.effect`; Electron main owns the command catalog adapter, child process, and validated view projection. The child—not the DSH Host—executes and reconciles extension React. The internal manifest parser admits reviewed artifact data; it is not another Cordis/plugin composition mechanism.

**Concrete proposed bridge:** follow the authenticated loopback conventions in `src/desktop-reveal-channel.ts`, `src/desktop-reveal-provider.ts`, `src/desktop-loopback.ts`, and `runtimeEnvironment()` in `src/main.ts:1098-1165`. Add a dedicated main-owned `DesktopTrustedRaycastChannel` with one fixed activation endpoint, a random per-DSH-generation bearer token, bounded exact-key activation body, and an abortable response stream carrying a single activation acknowledgment. Main registers the finite catalog only while that authenticated activation connection is live; Host disposal aborts and awaits the connection, and connection loss/DSH restart revokes activation and closes its command child. This is capability activation, not arbitrary fetch or method dispatch. Implementation must prove response-disconnect detection and teardown before relying on it; never graft new methods onto the reveal or dispatch routes. Supply runtime-generated endpoint/token only to the normal Desktop DSH process, exclude previews, scrub them from the extension child's explicit environment, and keep them out of renderer payloads. Credential minimization is defense in depth, not confinement of trusted account-level code. A single main-owned process manager receives catalog invocation directly once the Host activation and user-approved artifact are both current.

Disposal must be injected into existing main teardown beside launcher provider invalidation/window IPC disposal (`src/main.ts:2346-2379,3423-3424`): revoke owner/generation, abort/close transport, terminate child process group with bounded escalation, await exit, remove listeners, clean only private temp files, and prevent late events. Package notice/asset ledgers and `package-feasibility`-style build admission are required contract changes; no runtime install script.

## React execution and finite view contract (proposed, feasibility-gated)

Extension React 19 runs only in the trusted child with a pinned compatible `react-reconciler` custom host target producing serializable nodes and event handles. Server-rendered HTML alone cannot supply interactive hooks, and a child `react-dom` dependency is not required by this proposal. The launcher renderer remains React 18 and receives no extension code. Source-reached families include `List`, `List.EmptyView`, `List.Item`, `List.Item.Detail`, `List.Dropdown`/`.Item`, `ActionPanel`/`.Section`, plain `Action`, Copy/Paste/OpenInBrowser/Push/SubmitForm actions, and `Form`/`.Dropdown`/`.Dropdown.Item` in `LanguagesManager/AddLanguageForm.tsx`. Thus Form is required despite the separate `translate-form` command being excluded. Support navigation, fragments, text, icon/color descriptors, safe markdown details and loading/toasts. Derive any additional families from the reachable graph, not a full-store component catalog. No functions/components/raw React objects cross the wire; child event handles are wrapped in main-owned scoped IDs. Renderer detail/markdown rendering must disallow executable HTML and implicit remote-resource loading. Use existing semantic DSH tokens and public shared controls, visible focus, native keyboard semantics, reduced motion and localized first-party chrome; preserve upstream command copy.

Proposed pinned resolution: stage the extension and reviewed dependencies under an integrity-checked artifact root; alias `@raycast/api` and `@raycast/utils` to the compatibility SDK; resolve the pinned vendored translator and dependencies from that root; keep one React 19 singleton in the child. Do not alias the child to TockTeam React 18. Stop/replan if React 19/reconciler cannot produce the projection, if aliasing requires source patches, or if a dependency/license cannot be reviewed. The first approved implementation slice must run the unchanged `translate` module against the real endpoint; planning did not execute it.

Proposed view messages/types (new, finite, exact-key validated):
Main-to-child: `ViewOpen { sessionId, generation, command: "translate", preferences }` and validated `ViewEvent { sessionId, generation, revision, eventId, kind: "searchChanged"|"action"|"navigation"|"fieldChanged"|"submit", value }`. Child-to-main: `ViewReady { sessionId, generation, revision, root }`, `ViewPatch { sessionId, generation, revision, root, status }`, `ViewToast { sessionId, generation, toastId, style, title, message }`, `ViewError { sessionId, generation, class, message }`, and `ActionOutcome { sessionId, generation, eventId, succeeded, error? }`. Main-owned `ViewClose { sessionId, generation, reason }` ends the session. These are proposed discriminated unions with event-specific values (bounded search text, dropdown strings, or exact submitted form fields), not an arbitrary `unknown` payload. Main binds owner identity to the validated Electron sender and active child channel, never to caller-supplied identity. The renderer cannot publish ready/patch/toast/outcome or set lifecycle generation/hide policy. Native SDK requests use a separate finite request union for selected-text/copy/paste/open; child callback functions never cross the wire.

Initial protocol ceilings: 1 MiB message, depth 32, 4,096 nodes, 1,024 list/dropdown entries, 256 actions, 256 KiB total rendered text, 16 KiB search input and 128 KiB clipboard payload; overflow is an explicit compatibility error, never silent truncation. Validate these ceilings against the actual language catalog during the tracer slice. Main rejects unknown keys, wrong sender, stale generation/revision/event handles, non-serializable values and invalid descriptor URLs. Secret-bearing runtime environment/preferences are never automatically projected; arbitrary user-provided translation text cannot be guaranteed secret-free. The child-side `usePromise` implementation also needs per-request stale-result fencing: session/revision checks alone cannot distinguish an older network response rendered later. Closing may kill the process rather than cooperatively abort an upstream request that ignores cancellation.

Flow: catalog action -> main creates session and starts child -> first valid `ViewReady` within a 15-second startup deadline -> command becomes visible -> typed user events/patches -> close/crash cleanup. `LauncherSearchResponse` remains catalog-only. Add dedicated launcher-view subscription/input/close channels to the existing owned IPC and preload boundary; invoke still returns the existing catalog success/expired shape after initial ready. Register the catalog action with the existing main-owned `hideWindowAfterInvocation: false` (`src/launcher-actions.ts:15,376`, `src/main.ts:2248`). Count one successful launch at initial ready via existing success observation; failure before ready does not rank, subsequent service failures do not erase a successful launch, and UI events/keystrokes do not rank. No new child-supplied hide-policy field is needed. Native Paste closes only under its main-owned presentation policy and restores the captured target app; simple copy/navigation keep the command view open.

## Reachability and disposition

| Reached source behavior | Owner/disposition | Initial proof or failure |
|---|---|---|
| `hooks.ts` `getSelectedText` auto-input | Main-owned selection adapter, explicit permission/error -> empty input; never aliases clipboard | Prove existing Desktop selection owner/permission route or mark auto-input unavailable with visible status; manual input always remains. |
| `Action.CopyToClipboard` | Main/host-bound clipboard owner; bounded text | Copy success/denial is a typed action outcome. |
| `Action.Paste` | Main-owned prior-app focus + native paste owner; denial is visible failure | Must restore/focus prior app, paste, and report denial; never pretend clipboard copy is paste. |
| List search, 500 ms debounce, loading/results/details | Child React19 renderer -> finite view projection; main validates generation | Stale results dropped; close cancels publication. |
| Language manager, saved sets, add/delete/remove-all, dropdown/accessory/navigation | Child state + finite state events; persisted state is scoped to extension data root | All nested controls are covered by event handles; bounded list and depth. |
| Translation and proxy preference | Trusted child direct Node networking; source proxy preference may reach `HttpsProxyAgent` | Do not use main fixed-origin helper; real Google endpoint with fixed text; outage distinct from defect. Broad trusted networking is approved. |
| TTS `https.get` + `afplay` | Initial proof macOS-only; each invocation gets private TMPDIR/TMP/TEMP and its own process group; cleanup owns only that directory | Prove `os.tmpdir()` honors the environment and do not delete user paths. The upstream callback is fire-and-forget and does not report completion to `Action`; do not fabricate per-audio success/HTTP/write/spawn outcomes. Prove audible success, repeated activation, close-during-download/playback, bounded termination and temp cleanup separately. Concurrent TTS calls share a filename even within one invocation: if exact pinned behavior cannot pass this gate without patching source, stop and seek a compatibility exception rather than silently disabling or rewriting it. |
| Open Google Translate URL | Main-owned browser open with fixed HTTPS URL shape and bounded text | Validate URL; browser failure is typed. |
| Separate `translate-form`/quick/instant commands | Explicitly unsupported; manifest admission is only `translate` | Reject those command launches, but support the nested Add Language Form reached inside `translate`. |

Initial native proof targets macOS on the current machine; other platforms are not declared compatible. Selection and Paste are explicit feasibility gates for new native adapters, not existing launcher capabilities. Hold only the prior-app identity needed for focus restoration; do not retain selected text or query history beyond command state and declared extension storage.
