# Plan: Selective Oh-DSH v0.2.0 Ports

## Context

The immutable audit in `.beads/reports/2026-09-12-oh-dsh-v0.2.0-audit.md` reviewed all 34 commits and 67 final changed paths from Oh-DSH `v0.1.12` (`19262643092f801b5db9f70c0995acdfe813311e`) through `v0.2.0` (`c6fdd2705f70a077755ce64315ce5265c632f475`).

The user selected **Everything Worth Considering**: plan the response-image export, focused pinned-summary improvements, missing regression coverage, a gated Desktop update indicator, and gated coverage integration.

This remains a behavioral port, not a merge. Oh-DSH pins DSH `0.1.2-alpha.3`; TockTeam's authoritative `dsh-source.json` pins `0.1.2-rc.1`. Official DSH RC.1 contracts and TockTeam ownership remain authoritative.

## Problem

TockTeam lacks two useful browser behaviors and several narrow regression checks found in the audited release:

1. Users cannot save a finalized assistant response as an image.
2. The pinned summary lacks bounded expansion/copy, explicit states, safe rich presentation, and complete dialog semantics.
3. Marketplace, macOS installer, version, and updater security behavior have a few test gaps.
4. Update availability is visible only inside TockLauncher settings, not in the active Desktop shell.
5. The root suite has no bounded native coverage report, so CI publication cannot be judged from measured evidence.

Copying Oh-DSH directly would import incompatible alpha-era UI dependencies, foreign updater/DOM contracts, redundant staging machinery, expired model configuration, and upstream product identity.

## Solution

Deliver the useful behavior through existing TockTeam owners:

- Add one browser-only response-image plugin, composed on Desktop and Web and excluded from TUI.
- Deepen the existing pinned-summary plugin in place; do not replace its state, chrome, or layout contracts.
- Add only regression checks that exercise current public behavior; change production code only when a failing check proves a defect.
- Resolve the update-indicator interaction with an explicit human decision, then integrate any approved control into the existing Desktop React shell and `appUpdate` bridge.
- Add a dependency-free Node 24 coverage baseline first; publish coverage in CI only after a second explicit decision based on cost and scope.
- Advance the Oh-DSH skill baseline only after all approved work and evidence are committed.

## Design Read

Repeated developer-workbench interactions for TockTeam users, prioritizing immediacy, unobtrusive utility, keyboard access, and consistency with the existing shadcn/TockTeam UI system. Reuse existing `Button`, `Tooltip`, semantic tokens, Lucide icons, focus behavior, and chrome geometry; do not add decorative surfaces or another component/styling owner.

## User Stories

1. As a Desktop or Web user, I can download a faithful PNG of a finalized assistant response without granting new Host authority.
2. As a user reviewing an active session, I can read, expand, copy, and navigate the pinned summary with clear states and keyboard-accessible behavior.
3. As a maintainer, I can trust Marketplace, installer, version, and updater failure boundaries because focused regressions protect them.
4. As a Desktop user, I can notice an actionable update from the workbench if the approved indicator interaction adds value without misleading me.
5. As a maintainer, I can inspect honest root-suite coverage and explicitly decide whether CI publication is worth its cost.

## Implementation Decisions

### System Coherence

- **Source of truth:** DSH RC.1 owns chat slots and rendered turn contracts; `PinnedSummaryService` owns summary state/lifecycle; `DesktopAppUpdater` owns update state; Node's test runner owns coverage data.
- **Composition:** DSH Profile + Loader remains the only plugin composition mechanism. Desktop/Web patches enroll the response-image client; TUI does not.
- **State:** no duplicate response store, summary store, updater store, or coverage service.
- **Side effects:** PNG download remains browser-local. Cordis effects own client registrations/subscriptions. Existing updater IPC and parsing remain unchanged unless the redaction regression proves a defect.
- **Cleanup:** object URLs, subscriptions, focus restoration, client unload, Playwright sessions, Electron, Web servers, and descendant processes must all be released.
- **Failure policy:** image capture reports a local visible failure; summary degrades to verified plain states; update controls hide when disabled/unactionable; coverage remains report-only unless explicitly promoted.

### Response Image

- Use the RC.1 `conversation.chat.assistant-actions` contract owned by `dsh-client-ui-chat` and verify current `data-chat-flow-kind` / `data-turn-tail` behavior.
- Create one `@tockteam/save-as-image` browser package with a no-authority Host loader entry only because bundled package contracts require it.
- Use `@tockteam/ui`, Lucide, static Tailwind classes, and TockTeam locale conventions. Do not add or alias `@deepseek-ai/dsh-client-ui-primitives@0.1.2-alpha.3`.
- Bundle the smallest suitable capture dependency only if the first failing executable check proves native canvas/browser APIs are insufficient. The audited `html-to-image` algorithm is the candidate, not an automatic dependency decision.
- Keep structural turn lookup bounded; sanitize filenames; retry high-resolution capture once at normal resolution; always revoke object URLs.

### Pinned Summary

- Preserve `OPEN_KEY`, current compaction-first derivation, text-block filtering, same-ID binding replacement, `mountChromeSurface`, `SUMMARY_ROOT_CLASSES`, panel ownership markers, and mutual exclusion.
- Add only RC.1 fixture-backed fields. No guessed artwork projection or duplicate Git/PR dashboard.
- Prefer safe DOM construction and `textContent`; if minimal Markdown is retained, allow only the small audited subset and `http`/`https` links with safe external-link attributes. Add no Markdown dependency.
- Treat the surface as TockTeam's persistent, layout-reserving pane—not Oh-DSH's floating menu.

### Desktop Update Indicator

- Human decision `tockteam-9lt.11` must define placement and action before implementation.
- Recommended direction: a small Desktop-only control inside the existing `DesktopWindowTitlebar` or `DesktopAppRail`, using shared `Button`/`Tooltip` and the existing parsed `window.dshDesktop.appUpdate` bridge.
- Visible statuses are `available`, `downloading`, and `downloaded`; disabled, idle, checking, error, Web, TUI, and development-disabled states remain hidden.
- Do not add a standalone package, DOM mutation observer, custom updater window, new IPC, browser secret, or second updater authority.
- Rejection is a valid completed decision and closes the implementation issue as not applicable.

### Coverage

- Start with Node 24's native `--experimental-test-coverage`; add no coverage dependency or threshold.
- Label the result as root-suite coverage. It does not imply coverage of TockTutor, packaging, Nix, installed smokes, or browser flows.
- Run coverage once, not across the four-platform matrix, unless measurements justify it.
- Human decision `tockteam-9lt.14` must approve artifact or Codecov publication. Any action is pinned by full SHA, least-privileged, and uses no committed credential.

### Audit Baseline

- Keep `.agents/skills/oh-dsh/SKILL.md` at `v0.1.12` until every approved port, explicit rejection, focused check, real-surface proof, report, and decision is committed.
- After the final gate, update only the skill body below frontmatter, validate with `skill-validator check --strict .agents/skills/oh-dsh`, and commit the evidence.
- Do not modify `AGENTS.md`; its stale runtime row requires separate explicit permission.

## Testing Decisions

### TDD

Each non-trivial slice follows red → green → refactor. Run the narrow failing check first and commit coherent green slices frequently. Production behavior changes only where the failing check proves the current behavior is missing or unsafe.

### Highest Useful Seams

| Area | Highest useful seam |
| --- | --- |
| Response-image capture | Real finalized assistant action and downloaded PNG in the actual Web UI; final Desktop smoke after Web proof |
| Pinned summary | Real Web-based pane interaction plus focused pure/lifecycle/layout tests |
| Marketplace | Existing `PluginMarketplaceManager` public dispatch behavior |
| macOS installer | Real temporary bundle trees through `replaceMacBundle()` |
| Product version | Temporary source/packaged layouts through exported version resolvers |
| Updater redaction | `createDesktopAppUpdater()` state/listener output with credential-shaped failures |
| Update indicator | Existing Desktop React shell with the real parsed `appUpdate` bridge |
| Coverage | Node 24 root test command runtime/output plus one chosen CI lane |

### Browser and Desktop Proof

- Use Playwright CLI at 1512 × 949 CSS pixels with 2× device scale when capturing evidence; record exact geometry, route, mode, visible state, theme, and console/runtime errors.
- Verify light, dark, long/localized content, keyboard focus, reduced motion where applicable, and narrow/wide layout.
- Publish only allowlisted screenshots transactionally.
- Record the root PID/process group for every app/server/browser verification and stop the full descendant tree in `finally` or a shell trap.
- Do not use `pnpm start` or `pnpm start:fresh`.
- Run `pnpm test:launcher:electron` only after focused Web/component checks pass and only because the selected work affects Desktop browser behavior.
- Run `pnpm test:launcher:installed` once after all focused/package gates pass; never concurrently with package-boundary checks.

## Out of Scope

- Wholesale Oh-DSH parity, merge, rebase, submodule, or history import.
- Runtime downgrade/upgrade or alpha/RC dependency mixing.
- DeepSeek V4.1 Flash catalog entry, model defaults, or TUI model override.
- Oh-DSH updater subsystem, updater window, command router, scheduled install, or cancellation API.
- Browser-visible updater authority on Web or any updater UI on TUI.
- Git/PR or artwork sections in pinned summary.
- Oh-DSH branding, README hero, release version, notes/pairing system, shell installer, or second staging helper.
- Coverage thresholds or a whole-repository coverage claim without a separately measured and approved contract.
- `AGENTS.md` correction without explicit user permission.

## Risks and Mitigations

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Alpha-era UI imports break RC.1 runtime | High | Use current `ui-chat` contract and TockTeam UI; reject alpha package/alias shortcuts. |
| DOM/canvas capture clips or taints content | High | Bounded retries and pixel scans plus real Markdown/image/font/overflow browser evidence. |
| Async capture survives unload or wrong session | Medium | Cordis-owned effect cleanup, action-local state, object URL cleanup, lifecycle browser test. |
| New package breaks offline staging or React singleton | High | Existing build/stage owners, frozen closure, package/graph tests, packaged Web/Desktop smoke. |
| Summary port replaces existing correct behavior | High | Preserve current source-of-truth fields and tests; adapt only missing content/interaction behavior. |
